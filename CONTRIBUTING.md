# Как участвовать

По-русски. Issue, pull request, обсуждение — на русском языке, и это не
формальность: проект существует потому, что русскоязычному разработчику
приходится объяснять свою задачу на чужом языке в чужом трекере. Английский
тоже примут, никто не развернёт.

## Быстрый старт

```bash
git clone https://github.com/theasder/orakul.git orakul && cd orakul
cd app && swift build          # Swift 5.9+ (Xcode 15+)
swift test                     # тесты приложения
cd ../mvp && swift test        # тесты ядра: словарь, поиск, коннекторы
cd .. && npm test              # тесты страницы, текстов и идентичности
```

Руками ставить не нужно ничего. Но первая сборка `app/` скачивает 27 пакетов:
четыре прямых — WhisperKit, FluidAudio, MCP SDK, ViewInspector — и двадцать три,
которые тянутся за ними (swift-nio, swift-crypto, async-http-client и прочая
серверная обвязка). Столько же строк `Fetching` вы и увидите; проверено сборкой
из чистого клона 2026-08-13. Нужна сеть и несколько минут. `mvp/` и `npm test` не тянут ничего: в
`package.json` зависимостей нет вовсе, тесты страницы гоняет сам Node.

**Если добавили файл в `mvp/Sources/OrakulCore` и сборка приложения его «не
видит».** Ошибка выглядит как `cannot find <Тип> in scope`, хотя файл на месте
и импорт есть. SwiftPM держит список файлов зависимости-по-пути в кеше и нового
файла там не замечает; дата на манифесте не помогает, список считается по
содержимому. Лечится одной командой:

```bash
cd app && swift package clean && swift build
```

**Если сборка установщика останавливается на профиле нотаризации.** Сообщение
называет команду: `xcrun notarytool store-credentials meetgpt-notary`. Пароль
вводит человек — он не хранится в репозитории и не должен. Проверка стоит
первой, до компиляции: 2026-08-13 профиль пропал из связки, и выяснилось это
после шести минут сборки arm64.

Сборка установщика делает это сама (`app/build.sh`), а обычная — нет: чистка
стоит две минуты, и платить их на каждой правке не за что.

## Что попадёт в проект быстрее всего

1. **Русские строки на экранах.** Задача с известным числом: из 446 строк,
   которые человек читает в `app/Sources/MeetGPT/Views` и `Onboarding`, 23 не
   содержат ни одной кириллической буквы. Это верхняя граница, а не список
   работ: в остатке имена (`GitHub`, `orakul`), голые подстановки (`"\($0)"`) и
   кавычки вокруг цитаты — переводить там нечего. Английское предложение на
   этих двух поверхностях не осталось ни одного, поэтому правка тут — про
   новый экран, а не про старые.

   Число держит `test/russkie-stroki.test.mjs`, и держит в обе стороны:
   выросло — набор красный, уменьшилось — тоже красный, потому что потолок
   надо опустить в плане (`docs/ROADMAP.md`, §6.4). Не берите однострочник на
   `grep` из плана как проверку: он построчный и не видит вызов, разнесённый на
   две строки.

2. **Коннектор к российскому сервису.** Это главный дефицит и главная причина,
   по которой orakul вообще отдельный продукт. Битрикс24 подключён 2026-08-13,
   но по документации, а не на живом портале — если у вас есть портал, самое
   ценное сейчас это одна команда из §2.0.1 плана и ответ, работает ли поиск.
   Обход списка закончен, перепись — в §2.0.3 плана: пять подключены, три
   нет, у каждого «нет» названа причина. **Мегаплан отпадает** (нет
   долгоживущего ключа, вход логином и паролем), **Аспро.Cloud** ждёт
   описания метода списка задач с параметром поиска и формой ответа. Найдёте
   его — это работа на день, и она нужна. WEEEK подключён после публикации
   открытого справочника API.

   Если сервис ставят себе, живая проверка не упирается в аккаунт:
   `bash scripts/zhivaya-proba.sh gitea` поднимает сервис в контейнере,
   наполняет задачами, ищет и удаляет контейнер. Так проверены Gitea и Redmine;
   добавить туда свой сервис — тоже полезная правка.

   Секрет передаётся **заголовком**, даже когда у сервиса штатный способ —
   «?key=…&token=…». Адрес пишется целиком в журналы прокси, в журнал доступа
   самого сервиса и в отчёты об ошибках, и живёт там дольше отозванного ключа.
   У Trello ровно этот случай: взят заголовок OAuth. Манифест с `{token}` или
   `{basic}` в пути или в параметрах запроса просто не загрузится.

   Образец — `mvp/Sources/OrakulCore/RussianTrackers.swift`,
   чертёж с объяснением каждого решения — `docs/RESEARCH-AND-PLAN.md`, §2.2.

   Начинать удобнее с формы «Новый коннектор» (New issue → Новый коннектор): она
   спрашивает ровно те четыре вещи, на которых сервис проходит или не проходит —
   метод, адрес, параметр поиска, форму ответа. Не нашли какую-то из них в
   справке вендора — заводите issue всё равно и напишите, чего там нет: так
   закрылись Яндекс Вики и Teamly, и это записано, чтобы никто не искал второй
   раз.

   **Часто коннектор — это файл JSON, а не файл Swift.** Ответы на те же четыре
   вопроса кладутся в `mvp/Sources/OrakulCore/Resources/connectors/<сервис>.json`,
   и дальше их исполняет общий движок: дедлайн, различимые ошибки и правило
   «незнакомый ответ — отказ, а не пустая выдача» достаются даром. Так описаны
   Gitea, GitLab, Redmine, Outline, Пачка, Plane, GitFlic и BookStack — можно
   смотреть на них как на образец. Plane и GitFlic отличаются: поиска по слову у
   них нет, и они показывают перечисление с границей (ниже про `scan`).
   BookStack показывает другое — `stripTags`: он подсвечивает найденное прямо в
   тексте, а `<strong>` в подсказке, которую читают вслух на звонке, не нужен.
   Wiki.js — как описать GraphQL: весь запрос лежит в теле, а отказ приходит
   кодом 200, поэтому слова сервиса берутся из `errors[0].message` (в пути
   можно ставить номер — это шаг в массив). Nextcloud — как быть с Basic:
   `{basic}` переводит токен в base64, и человек вписывает «имя:пароль
   приложения» одной строкой, ничего не кодируя руками. Trello — как отдать
   сервису два значения: секрет остаётся токеном, а несекретный ключ
   приложения объявляется в `parameters` и уезжает в заголовок вместе с ним.

   **Облачный сервис адреса не спрашивает.** Если сервис один на всех
   (`api.linear.app`, `api.trello.com`), адрес пишется в коде рядом с
   перечислением, а не в поле настроек: лишнее поле — это лишняя опечатка,
   из-за которой человек будет искать причину в своём токене. Такие коннекторы
   живут в `WesternTrackers.swift`.

   ```json
   {
     "id": "сервис", "title": "Сервис",
     "docs": "https://ссылка/на/метод/в/документации/вендора",
     "verifiedOn": "2026-08-18",
     "request": {
       "method": "GET", "path": "/api/v1/search",
       "query":   [{ "name": "q", "value": "{query}" },
                   { "name": "limit", "value": "{limit}" }],
       "headers": [{ "name": "Authorization", "value": "Bearer {token}" }],
       "body": null
     },
     "response": {
       "list": ["data"], "title": ["title"], "author": ["user_id"],
       "context": null, "key": [], "state": ["state"]
     }
   }
   ```

   Подстановки: `{query}` — слово человека, `{limit}` — сколько строк просим,
   `{token}` — ключ из Связки ключей. Пути (`["document","title"]`) читают
   вложенные поля. Тело — шаблон строкой, если поиск идёт `POST`-ом, как у
   Outline; кавычки в слове экранируются сами.

   Два поля обязательны, и без них манифест не загрузится: `docs` и параметр
   (или тело) с `{query}`.

   **Если поиска по слову у сервиса нет.** С 2026-08-18 это не приговор
   (роадмап, §7.2). Список задач принимается — но только объявленным списком, и
   всё три условия проверяет код, а не ваше слово:

   ```json
   "scan": {
     "pages": 5, "perPage": 100,
     "page":  [{ "name": "cursor", "value": "{perPage}:{page}:0" },
               { "name": "per_page", "value": "{perPage}" }],
     "match": [["name"], ["description"]],
     "more":  ["next_page_results"],
     "total": ["total_count"]
   }
   ```

   `pages` × `perPage` — граница на один вопрос; больше десяти страниц движок
   не даст. `match` — поля, по которым слово ищется у нас; пустой список
   означает «список вместо поиска», и манифест не загрузится. `more` — где
   сервис говорит, что дальше есть ещё; без него конец списка определяется по
   короткой странице. `total` — где он называет полный размер.

   Зачем `total`: движок отдаёт вместе с выдачей охват, и человек видит не
   «ничего не нашлось», а «не нашлось среди последних 500 из 40 000». Это
   разные ответы. Если список кончился раньше границы — так и говорится, и
   тогда ответ полный.

   **Если адрес требует не только хост.** У Plane номер проекта стоит внутри
   пути. Такие поля объявляются, и человек заполняет их сам:

   ```json
   "parameters": [{ "name": "project", "title": "Проект", "example": "550e8400-…" }]
   ```

   Подстановка, которую никто не объявил, манифест не загрузит: `{project}`
   уехал бы в адрес буквами, сервис ответил бы 404, и человек прочёл бы это как
   поломку, а не как незаполненную настройку.

   Чего манифестом не описать — и это нормально: Mattermost отдаёт сообщения
   словарём, Zulip требует Basic-авторизации из двух половин, Matrix — вложенного
   тела, Битрикс24 держит ключ в пути. Такие сервисы пишутся кодом, образец —
   `WorkMessengers.swift`.

   **Доменный пакет словаря.** Пакетов может быть сколько угодно: любой
   `*.json` в `mvp/Sources/OrakulCore/Resources/lexicon/` подхватывается
   загрузкой. Формат тот же, что у `base.json`, а правил между пакетами два, и
   оба проверяются при загрузке:

   - одно слово не может чиниться по-разному в двух пакетах. Иначе побеждает
     тот, чьё имя файла раньше по алфавиту, — то есть починка зависит от имени
     файла;
   - слово, которое ваш пакет чинит, не должно стоять в чужом списке
     `ordinary`. Эти списки — накопленные отказы («агент» — страховой агент), и
     отменять их молча нельзя. Считаете отказ ошибкой — это отдельный разговор
     и отдельная правка.

   Имена инструментов (`infrastructure`) под второе правило не подпадают: они
   работают только на поиск, и «редис» обязан остаться овощем в расшифровке.

   И главное: пакет — это утверждение о том, что люди в такой роли
   действительно говорят. Проверяется оно корпусом (ниже), а не составляется по
   памяти.

   **Если хотите помочь с корпусом речи.** Самое ценное, чего не хватает, —
   записи русской технической речи с расшифровкой (роадмап, §6.3). Корпус — это
   папка с `corpus.json`:

   ```json
   {"items": [
     {"id": "doklad-1", "genre": "talk", "consent": "public",
      "source": "https://example.com/доклад", "seconds": 900,
      "reference": "doklad-1.reference.txt",
      "engines": {"whisper-large": "doklad-1.whisper.txt"}}
   ]}
   ```

   `genre` — доклад или звонок; складывать их в одно число нельзя, доклад
   читается ровнее. `consent` — на каком основании запись у вас: `public` у
   опубликованного доклада, `participants` у звонка с согласием участников.
   Записи без ответа на этот вопрос не принимаются — на звонке звучат чужие
   голоса. `reference` — расшифровка, размеченная человеком; без неё считается
   только расхождение движков, с ней — настоящий WER.

   Проверить перед отправкой: `bash scripts/corpus-check.sh /путь/к/папке`.

   **Как показать, что коннектор работает, не показывая токен.** Проверка идёт
   на живом сервисе — значит, её может сделать только тот, у кого там аккаунт, а
   принять правку должен тот, у кого аккаунта нет. Между вами нужен документ:

   ```bash
   ORAKUL_TOKEN=… ORAKUL_HOST=… orakul спросить <сервис> тарифы
   ```

   Отчёт показывает, что ушло на сервер и что он ответил: метод и адрес,
   заголовки, код ответа, узналась ли форма и сколько строк пришло. Токен из
   него вычищается — по имени заголовка, по значению, по половинкам составного
   ключа и по процентной кодировке, если ключ уехал в адрес. Это закреплено
   набором `ConnectorProbeReportTests`, и проверяется там именно утечка, а не
   формат вывода: вставлять этот текст будут в публичный пулл-реквест.

   Всё равно перечитайте отчёт перед отправкой. Сервис мог вернуть в теле
   что-то своё — имя сотрудника, адрес внутреннего сервера, название закрытого
   проекта, — и вычистить это за вас никто не может.
3. **Слова, которых не хватает словарю.** `RussianLexicon` чинит расшифровку
   после распознавания, и его таблица собрана по одному замеру. Термин, который
   у вас на звонках слышится неправильно, — это готовая строка в неё.

   Это тоже данные, а не Swift: `mvp/Sources/OrakulCore/Resources/lexicon/base.json`.
   Аббревиатуры (`acronyms`) пишутся латиницей заглавными, заимствования
   (`loanwords`) — кириллицей: расшифровка русского звонка, где половина слов
   латиницей, читается как чужая.

   Три правила проверяются при загрузке пакета, а не на ревью:

   - **слова языка не берут.** «Агент» — это страховой агент, «ветка» — ветка
     дерева. Починка такого слова портит нормальную фразу, поэтому список
     `ordinary` их держит, и попытка добавить оттуда слово роняет загрузку;
   - **дублей нет.** Два канона у одного слова означают, что результат зависит
     от порядка обхода;
   - **алфавит соответствует половине.** `АПИ` в аббревиатурах или `prod` в
     заимствованиях чинят слово в обратную сторону — ровно то расхождение
     движков, ради которого словарь и написан.

   Отказ приходит с объяснением, а не с кодом ошибки. Если ваше слово в него
   упёрлось — напишите об этом в issue: список `ordinary` пополняется как раз
   такими случаями, и отказ, записанный однажды, экономит следующему человеку
   тот же вечер.
## Правила, о которые ломаются чужие пулл-реквесты

**Не заявляйте того, чего нет.** Кнопка «Подключить» к сервису, у которого нет
подходящего API, хуже отсутствия кнопки. Прежде чем добавлять коннектор,
проверьте в документации вендора метод, адрес, параметр поиска и форму ответа —
и сошлитесь на неё в комментарии. Два сервиса из первой пятёрки трекеров
выпали именно на этой проверке, и это правильный исход.

Сюда же относится пустая выдача вместо отказа. Не всякий сервис пользуется
кодами HTTP: Битрикс24 отвечает `200` и кладёт отказ в тело, поэтому тело
проверяется до разбора списка. И пустой список принимается только знакомой
формы: ответ без единого известного ключа — отказ, а не «ничего нет». Иначе
отозванный ключ покажется человеку как «задач не нашлось», и он заведёт вторую
поверх существующей. Подробнее — §2.2 плана, пункты 5.1 и 5.2.

**Каждая функция закрыта тестом.** Не «есть тесты», а: тест падает, если
функцию сломать. Тест, проверяющий выдуманный адрес, проходит и не значит
ничего.

**Тесты не ходят в сеть.** HTTP передаётся снаружи (`RussianTrackers.HTTP`),
ключи — в фальшивую Связку ключей (`InMemoryKeychain`). Тест, который ходит в
Яндекс Трекер, проверяет Яндекс Трекер.

**Ничего платного.** Тарифов, лимитов и платных экранов в orakul нет; это
закреплено `NoTariffsTests`. Функция, доступная «только на плане», в проект не
попадёт.

**Данные не покидают компьютер.** Запись, расшифровка и поиск считаются
локально. Кнопка, которой нужна наша сеть, не проходит проверку при сборке.

Один зелёный прогон — не результат. Набор большой и идёт параллельно, поэтому
тест, берущий общее состояние у соседа, падает не каждый раз. 2026-08-13 таких
нашлось два: один проверял предусловием сессию, которую выставляют другие
наборы, второй требовал конкретного первого места в ранжировании, а оно зависит
от того, успел ли построиться индекс эмбеддингов. Оба падали примерно раз в пять
прогонов и оба ничего не сообщали о продукте.

Ловятся они циклом с сохранением вывода, а не `swift test | grep`: в живом
выводе виновник дважды не нашёлся.

```bash
for i in 1 2 3 4 5; do
  swift test > /tmp/run$i.log 2>&1
  grep -q "failed after" /tmp/run$i.log && { grep -n "recorded an issue" /tmp/run$i.log; break; }
done
```

Правили тесты — прогоните весь набор несколько раз.

**Скорость проверяется отдельной командой.** Бюджеты задержки — поиск по году
звонков, восстановление терминов в двухчасовой расшифровке — закрыты тестами,
которые обычный `swift test` пропускает: на занятой машине они меряют не код, а
соседний компилятор. Правите `DecisionRecallService`, `GlossaryRestore` или
индекс — прогоните их сами:

```bash
cd app && CRUXWING_PERF=1 swift test --filter Performance
```

Замер на этой машине 2026-08-13: поиск по 250 звонкам — 2,04 с (лучшее из
трёх), восстановление двухчасовой расшифровки укладывается в послезвонковый
бюджет. Зелёный обычный прогон об этом не говорит ничего: без переменной оба
набора помечаются пропущенными и попадают в общее число как пройденные.

**Секреты — только в Связке ключей.** Ключи провайдеров и токены трекеров живут
в Keychain (`ProviderKeyStore`, `RussianTrackerStore`), никогда в UserDefaults и
никогда в коде. Пустая строка убирает запись, а не сохраняет пустоту: иначе
очищенное поле оставляет мёртвый ключ, и сервис выглядит настроенным.

## Если правка задевает ядро — проверьте Linux до отправки

```bash
bash scripts/proverka-linux.sh    # ~40 секунд, нужен docker
```

Ядро собирается на двух системах, и разница между ними не теоретическая:
`URLSession.bytes(for:)` и `waitsForConnectivity` есть только у Apple, а на
Linux первого нет вовсе, второе доступно только на чтение. Обе правки приехали
одним коммитом, на macOS собирались, все наборы были зелёными, и четыре дня
никто не знал, что командная строка не собирается для своей второй системы.

Скрипт делает то же и в том же образе, что задание `linux-core` в CI, — это
сверяется проверкой `test/proverka-linux.test.mjs`, чтобы «локально сходится»
не начало значить меньше, чем кажется.

## Прогон части проверок

`swift test --filter Имя` при опечатке в имени печатает

```
✔ Test run with 0 tests passed after 0.001 seconds.
```

и возвращает ноль. Опечатка выглядит точно так же, как успешный прогон, — и
это не теория: за одну ночь я купился дважды, один раз решив, что проверка не
ловит мутацию, хотя она просто не запускалась.

```bash
bash scripts/test-filter.sh mvp RussianCaseSearchTests
bash scripts/test-filter.sh app AgendaCheckServiceTests
```

Скрипт падает, если под фильтр не попало ни одной проверки. Фильтровать надо по
имени структуры набора: кириллические названия из `@Test("…")` в фильтр не
попадают.

## Если запускаете сборку образов

`cd app && bash dist-all.sh` собирает две архитектуры и идёт около десяти минут.
Пока она идёт, репозиторий заморожен: правка любого файла в `app/Sources` или
`mvp/Sources` роняет её с `input file ... was modified during the build`, а
коммит посреди сборки даёт два образа, заявляющих разные коммиты.

Проверять надо не глазами:

```bash
bash scripts/build-running.sh && echo "нельзя править" || echo "можно"
```

Скрипт узнаёт сборку по рабочему каталогу процесса, а не по строке запуска:
сборка стартует как `cd app && bash dist-all.sh`, и пути в её командной строке
нет вовсе — шаблон `pgrep -f "orakul/app.*dist-all\.sh"` не совпадал никогда и
молча разрешал править. Чужая сборка из `/tmp` при этом за свою не принимается.
Обе стороны закрыты проверками в `test/build-running.test.mjs`.

Безопасно во время сборки: `test/*.mjs`, `public/*.html`, `README.md`, `docs/`,
`scripts/` — в отпечаток исходников входят только два каталога `Sources`.

## Оформление

Коммиты: `тип: что сделано` — `feat`, `fix`, `refactor`, `docs`, `test`,
`chore`, `perf`. Первая строка по-русски, до 72 символов.

Комментарии в коде объясняют **почему**, а не что: «что» видно из кода.
